# Known limitations and demo risks

Ordered by effect on judging/demo; statuses are deliberately narrow.

1. **Challenge/access blocker — NOT VERIFIED:** original organizer rubric, eligibility, deadline/event timezone and required judge/public access. App is intentionally private, and no repository/submission has been published. SSH/runtime evidence exists; Cloud Manager VM resource screenshot, region and resource label remain unverified. Resolve these externally before claiming challenge compliance.
2. **AI reliability — FAILED in an observed normal run:** KC evaluation c09838c5-b14f-4cc0-84ef-5f11d128ffef had five successful tools but AI degraded with ValueError. The exact rejected selection was not logged; precise cause is unverified. Natural deterministic recommendation and human approval worked. Warning runs had active AI. Do not promise every run will have an active generated brief or loosen validation to hide the failure.
3. **Live hazard availability:** a saved synthetic site name is not evidence of a current warning. Captured warning expires 2026-10-10T22:30:00Z. Tomorrow's demonstration must fetch anew or explicitly show REPLAY. No live high-wind or high-AQ trigger was verified at the fixed sites; cutoff/applicability branches have synthetic tests.
4. **Operational authority/data:** office, shift, supervisor and twelve staff are synthetic; this is not a USDA operating system. Local access/building/travel conditions were not physically verified. Supported warning overlap covers only part of the tested two-hour shift. Expiry/zero alerts is not a safety guarantee. Notice-minutes is stored facility context, not a full operational notice-compliance engine.
5. **Rules and confidence:** only flood/high-wind warning and modeled AQ mappings are automatic. Watch/advisory/other hazards require human review when applicable. Office action mappings, freshness budgets and confidence are engineering assumptions. Confidence is not probability. Delay/dismissal are human selections requiring timing/basis, not automatically forecast closing times.
6. **Notifications:** drafts/queued_demo only; no actual transport, delivery receipts or enterprise roster integration. Channel is a routing label, including accessible voice preference. Deferred follow-up is an explicit manual supervisor step; no scheduler/job executes it.
7. **Evidence/model limits:** modeled CAMS grid AQ is not indoor sensing. The configured `hackathon-chat` alias does not establish the underlying model's verified vendor/version. Invalid output, provider failure or deadline exhaustion degrades AI while retaining available deterministic facts.
8. **Security/recovery:** private loopback + SSH and manager HTTP Basic; no enterprise SSO/public HTTPS. Environment files and keys remain outside Git. Host key was originally TOFU; subsequent connections are pinned/strict. SQLite immutability/hash checks detect ordinary record changes but do not certify compliance or prevent a privileged host administrator from tampering. Isolated SQLite-copy replay is tested; a full backup restoration into a separate running container has not been exercised.
9. **UI/demo scope:** screen/readability checks cover tested browser sizes, not full accessibility certification or every browser. Three-minute script is prepared; a stopwatch-verified human rehearsal is still unverified. No simulation/what-if UI, new framework, second agent or broader hazard architecture was added.

Acceptance fixes are limited to manual deferred follow-up, rule-version display, readable validation errors/long text, clearing prior manager inputs and clearing old evidence during a new collection. Existing historical records remain unchanged; older deferred drafts intentionally do not acquire the new follow-up text.
